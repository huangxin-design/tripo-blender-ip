# Blender 精修与验收

用于已有底模的局部修整、构图、材质、渲染及打包。以下顺序优先稳定构图和大形，再增加计算成本。

## 工程与机位

- 保留原始 GLB 和已有工程，另存带版本的工作文件。把基础角色、修补部件、毛发/羽毛、灯光、相机分组，便于撤回单项修改。
- 记录网格数量、面数、材质、贴图、包围盒、单位和轴向；不要靠“最大网格必定是人物”选对象。导入可能是多个网格，也可能所有部位粘成一块。
- 按实际尺寸归一化或保留已有单位，统一把地面与模型接触关系调好。2 米高度只属于参考案例，不能把坐姿、半身、动物或道具强制缩放成同样高度。
- 低分辨率看几个候选方位，匹配脸朝向、身体倾斜、肢体重叠和配件轮廓。依据透视特征选择正交或长焦透视，保留原图比例和边缘空间；不固定套用 +X 机位。
- 明确本次主视角。若后来要求转台/动画，重新检查不可见面、卡片、隐藏网格和接缝；固定视角可接受的修法不自动适合转动。

## 按部位修补

**脸与身份。** 对照眼睑开合、视线、瞳孔位置、嘴形、鼻耳和发际线。颜色不对用局部材质遮罩；轮廓或表情不对要局部几何调整。不要用黑色瞳孔覆盖来宣称已修复眼睑。遮罩可由选定面/顶点组、UV 区域或参考视角射线辅助获得，每个模型重新定位，避免旧图像像素坐标直接复用。

**规则硬表面。** 光环、圆钮、镜片、环扣、连接杆通常用基础几何或曲线重建更可控。匹配位置、方向、厚度，增加适量倒角和平滑法线。原部件先隔离/隐藏并检查没有残留双件，再替换；保留原始文件以便回退。

**分离粘连。** 先判断是独立连接岛、材质边界还是实质粘连。UV 缝会把同一点拆成多个顶点，简单边邻接遍历可能只抓到一小片。可用位置近邻辅助建立临时连通关系，但容差须按模型尺度选择，并结合部位、距离/法线和包围盒排除相贴的其他表面；不要全模型盲焊，避免破坏 UV 或把衣服与皮肤连上。范围不确定就改为明确选择或局部手工重建。

**毛发与羽毛。** 区分体积、主羽、次级羽片和表面纤维。先修体积与方向，再添加曲线/羽片。白色像素并不代表毛皮，必须联合对象、部位、面组/遮罩限制生成区域；金属反光、眼白、手套都要排除。曲线贴合表面、顺生长方向并渐细。用小样预览验证分布，再增加数量。不要把随机“叶片”撒满模型替代羽毛；大羽片需要方向、根部锚点、层叠和厚度。

**机械翅膀与手。** 检查薄片交叠、根部连接、尖端厚度、指关节和指间粘连。材质再亮也不能修复断裂/不合理连接；按主视角可见程度局部重建。

## 材质与调色

- Base Color 通常用 sRGB；Normal、Roughness、Metallic、AO 等数据贴图用 Non-Color。确认 normal 为 OpenGL 还是 DirectX，必要时显式转换，不凭文件扩展名判断。
- glTF ORM 的 R=遮蔽、G=粗糙度、B=金属度。追踪连接来源，别把 ORM 的 Separate Color 节点当成底色分离节点。
- 皮肤、纤维、布料、漆面、裸金属分开控制。混在一张图/一个材质里时用可靠遮罩分区，不能全模型统一加皮肤 SSS 或降低粗糙度。保留原 PBR 连接并检查法线强度。
- 自动化选择节点时用类型及输入/输出连接语义，不依赖可能被本地化的显示名称；同类型节点有多个时还要核对上游图像和下游用途。重复执行修改前检查已有自建节点，避免叠加两次调色。
- 先建立柔和主光、适量补光、能分开轮廓的边缘光与接地阴影，再调曝光和色彩。金属需要可读的环境反射，不能只调金属度。
- 调色以本次角色辨识度、主色和不同材质的层次为准，不直接套一个强滤镜。保存可比较的预览，检查饱和度变化是否损失设计特征；具体案例参数见 approved-case.md。
- 节点调色、灯光变化和外部贴图烘焙是不同交付。若只导出原贴图，要明确它们不含 Blender 中新增的局部改色/材质或新建几何。用户要跨软件保持外观时，先确定目标软件、渲染器和格式，再规划烘焙、导出和目标软件重新导入验收；逐项核对材质、几何、色彩管理和灯光兼容性。无法在目标软件核验时明确说明，不承诺外观一致。

## 渲染与失败处理

发现实际 Blender 路径后，在独立后台进程运行，避免影响用户打开的工程：

```text
<blender> --background --factory-startup --python-exit-code 1 --python <project-script.py>
```

这些参数隔离用户插件，并让脚本异常产生非零退出码；仍须检查日志、成功标记和输出。脚本/文件名与输出路径由本任务确定，不覆盖用户已有终稿。

- 先检测可用 Cycles 后端；NVIDIA 可选 OptiX，其他设备按实际支持选 CUDA/HIP/Metal/CPU。不硬编码显卡型号。设备首选项需要在本次进程设置，不能假设 `.blend` 保存了 GPU 首选项，也不需要改用户全局设置。
- OptiX 缓存不可写时，可仅为当前渲染进程设置 `OPTIX_CACHE_PATH` 到项目内目录。不要为渲染修改系统权限或终止其他任务的 Blender/GPU 进程。
- 预览优先较小尺寸与适量采样；细纤维/反射在终稿需更低自适应阈值。案例参考为最大 1024 samples、threshold 0.003、min 64、OIDN；这些是起点，不是最低合格线。
- 用户未指定标准时，长边 4096 保持参考比例；例如本案例 2748×4096，与 UHD 3840×2160 不同。终稿可用 RGB 16-bit PNG；透明输出按用户要求使用 RGBA，另确认背景/阴影策略。
- 明确 GPU 内存/后端问题可降低临时内存压力或回退 CPU；不要捕获所有错误后声称成功。回退后记录实际设备，并更新保存的工程。等待时间较长时向用户说明进度，不能把尚在渲染说成已经交付。

## 文件与视觉验收

1. 确认渲染进程成功，输出来自本次工作版本；实际读取图片文件核对宽高、位深、格式，完整解码检查损坏，不能只读 `scene.render` 设置。
2. 查看整图，再以原尺寸查看脸、手、头发/羽毛边缘、金属高光。检查裁切、穿插、杂毛、漂浮零件、锯齿、过度降噪、色偏和阴影。不能只看自动缩小后的预览。
3. 打包所有必需图像/资源，另存交付工程，再用独立 Blender 进程重新打开检查相机、对象与材质；渲染依赖缓存/外部字体等也须一起处理。仅 pack_all 成功不等于所有资源已验证。
4. 提取原始 packed bytes 时按文件头确认 JPEG/PNG/WebP，使用真实扩展名。数据贴图不能应用显示变换。新烘焙的贴图另存，不冒充原始数据。
5. 保存简短验收记录：图像实际宽高/位深、引擎/设备、采样上限、资源检查、视觉检查结果与仍存偏差。给可点击的图像/工程/贴图路径；远端签名地址不是持久交付。
