# Tripo 执行与恢复

用于新建、继续或检查 Tripo 任务。API 参数、当前模型与价格以当前安装技能、CLI 帮助和任务记录为准；本文件保留的是已遇到的执行风险与选择依据。

## 预检与计划

1. 检查参考图真实存在且可读；暂存图复制到本项目稳定输入目录。只有文字时先确定设计；不要为了走本流程擅自换掉用户选定的图。
2. 发现现有 Tripo 命令与 Blender 可执行路径。Windows 上检查 `Get-Command tripo`，再检查已知本机安装位置；不要仅因 `npx` 不在 PATH 就断言未安装 Node 或重装工具。
3. 用 `doctor` 检查当前认证、地区和余额。不要打印密钥、复制认证文件到项目，或擅自切换账号/地区。凭证问题按当前 Tripo 技能处理。
4. 确保项目输出目录可写，并注意 CLI 会写用户历史文件。若已知沙箱限制该位置，按工具权限机制处理必要的窄范围写入；不要改 HOME、扩大权限或将凭证迁入项目作为绕过手段。
5. 对拟执行的准确命令加 `--dry-run --json`。展示输入、CLI 模型别名及实际 wire model、每个 API 步骤、输出格式、每步与总费用估计。dry-run 的步骤是依据，不能只看预设名字或 deliverables 摘要。dry-run 不一定包含可靠实时价格，费用需当前文档/技能补充，并标成估计。
6. 当前任务已批准的具体方案直接执行；若尚未授权付费，按 Tripo 技能要求等待明确许可。不把这次安装技能或一次旧项目许可当作未来无限预算。未经授权不重抽、不批量试种子。

## 静帧参数选择

- 已验证案例采用高保真几何、详细 PBR 贴图、保留参考姿态与朝向。先让 CLI 自动选择，检查实际模型；低 `face_limit` 可能把请求切到低模系列。
- 固定静帧通常可直接从一张图生成，输出 GLB。无需为了“更专业”默认追加多视图、T-pose、绑定、格式转换或四边面。
- 案例所用的 `film` 预设曾额外开启 quad 并改变输出。不要盲用场景预设；核实真实 payload 和整个调用链，能直出 GLB 就不为未要求的 FBX 付费转换。
- `delight` 用于减少贴图里的烘焙光影，但依赖贴图版本，不保证完全清除。采用前检查当前支持条件。
- Tripo 分件输出与贴图可能有互斥约束。确有分件需求时读取当前 `generate_parts`、segment 或 smartsegment 参数，不默认沿用整体模型的 textured 参数。列全后续重贴图/补洞/装配步骤和费用。
- 只有模型缺陷影响当前目标、且本地修补代价明显更高时，才提出新的付费生成方案；先给当前结果与具体缺陷依据。

## 执行、恢复与去重

记录提交时间、输入、输出路径、任务 ID 和原始结果。正常生成等待 CLI 完成，不另外再起一套提交/轮询循环。标准输出与进度日志分开；`make --json` 取最终 JSON，`task watch --json` 可能是 NDJSON，取最后的任务详情。

**遇到提交后的权限错误、网络断开或超时，先进入“结果未知”，禁止直接重复 make：**

1. 若有任务 ID，用 `task get <id> --json` 查询。
2. 若未拿到 ID，查询 `usage --json`、`balance --json` 和可用任务记录，结合提交时间、输入/类型、模型识别候选任务。余额变化只能作线索，不是独立身份依据；有并发项目时不能认领“最近的那个”。
3. 唯一确认已有任务后，用 `task watch <id> --download -o <实际目录> --json` 或 `task get <id> --download` 恢复等待/下载，不重新生成。
4. 候选不唯一或服务端状态仍未知时，停止新的付费提交，报告证据并请求消歧。无结果或本地 exit 1 都不能单独证明未创建。
5. 已确认服务端终止失败后，再决定是否在既有明确重试预算内重试；超出授权需新方案。下载失败只重试下载。不要把退款规则套到客户端失败，实付以服务端账单为准。

真实案例：CLI 0.5.1 先创建任务，后写 `~/.tripo/history.jsonl` 时遭遇 EPERM，导致任务 ID 没有正常打印。通过 usage 找回并 watch 下载，仅付了一次费用。未写入历史时 `@last` 可能指向旧项目，应保存明确任务 ID。

## 文件和费用

- `make -o` 在已验证 CLI 中表示输出父目录，实际文件进入 `tripo-out/<name>-<id>/`；`task get/watch -o` 的行为可能不同。以本次输出记录的实际文件路径为准。
- 检查文件存在、体积、格式和模型可导入。预览文件曾被命名为 `.png`，实际却是 WebP；检查文件头，保留真实格式。
- 每一步记录 `credits_consumed`，有链时按唯一 task ID 统计，避免把链汇总和每步金额重复相加；缺失时查对应任务，不能用前后余额差归因于本任务，其他项目可能并发扣费。
- 保存本地交付文件与任务 ID，避免将短期签名 URL 当作永久链接。需要最新下载地址时查询对应任务，不复制签名 URL 进入技能或公开文档。
